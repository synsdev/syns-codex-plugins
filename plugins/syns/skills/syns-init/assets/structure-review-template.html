10 / test

Evaluation plan and thresholds

Sealed, matched and read-only. Prepared fixtures are regression evidence, not independent causal proof.

{{EVALUATION_PLAN}}

Matched conditions

The current snapshot and staged proposal receive the same source bytes, model, harness, prompts, limits, read-only tools, working depth, and network policy. Hashes are checked before and after.

Null means unobserved

Timing, tokens, and tool calls appear only when the harness reports them. Missing values remain null; they are never inferred from answer length.

11 / risks

Risks held at the gate

These controls explain what approval does not settle.

Digest drift

Any change to source snapshot, catalog, mapping, proposal, or evaluation plan invalidates this approval and requires a new review.

Package ≠ structure

If the proposal adds intent, indexes, routing, or canonical content, results concern the repository package—not folders alone.

No adoption implied

A better read-only result still authorizes nothing. Local adoption, a project adapter, and private publication remain separate later controls.

Decision · Gate A

Authorize the next safe step?

Only the exact digest-bound proposal may be materialized in an isolated private local stage and compared through read-only agents.

No selection is prefilled. Blank submission means no approval. Comments cannot substitute for a selected decision.

Read-only file preview: decisions can be submitted only from the local review server.

Required decision

Submission records the selected value and bound digests. It performs no filesystem or remote operation.
